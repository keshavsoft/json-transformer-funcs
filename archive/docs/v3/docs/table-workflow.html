The table story · src/v12

From table data to browser DOM

A table has a stable shape and changing content. This repo keeps those concerns in separate JSON pieces: data says what to show, templates say how repeated pieces look, a scaffold says where they belong, and a builder connects them. The finished JSON tree can be inspected before a renderer creates DOM elements.

data + templates→table scaffold→populated JSON tree→browser DOM

How an instruction connects the pieces

An instruction is a small routing record. It does not contain the data or markup; it names which data, template, builder function, and destination to use.

{
  "sourceKey": "columns",
  "templateKey": "buildHeader",
  "func": "collectionFromKey",
  "destinationPath": ["children", 1, "children", 0, "children"]
}
  • sourceKey selects inData.columns: the column names and other column properties.
  • templateKey selects sampleSpec.buildHeader: the JSON tag shape with placeholders.
  • func selects a named helper from the JavaScript function registry.
  • destinationPath walks the cloned table tree and replaces the target child array.

Read the destination from the scaffold

In the sample table.json, the root's children are ordered as colgroup, thead, tbody, and tfoot.

children[0] colgroup · children[1] thead · children[2] tbody · children[3] tfoot

Starting at the table root, this path goes to its second child (thead), then its first child (the header tr), then that row's children array.

table.children[1].children[0].children

That array is where the generated th nodes go. The footer instruction uses the same column source and helper, but points to the tfoot row. The colgroup uses width data and a col template. The body uses records and a row/cell template.

This is how the cases relate: each instruction fills one part of the same scaffold, and the table is complete when the required destinations have been populated.

What the JavaScript does with it

The instruction loop resolves the names in JSON, calls a helper, then writes its result into a cloned table object.

const input = {
  source: inData[instruction.sourceKey],
  template: sampleSpec[instruction.templateKey]
};

const result = functionRegistry[instruction.func](input);
setByPath(table, instruction.destinationPath, result);

Repeat a template over columns

collectionFromKey maps over the source array. For each item it clones the template and replaces placeholders such as ${columnName} in text, attributes, and nested children. The same column data can therefore build header labels and footer input names.

Turn each record into cells

collectionFromInternal clones one outer row template per record, then creates an inner cell for each value in Object.values(record). The cell template receives each value as ${rowValue}; property order must match the displayed column order.

tableFromData is the direct v12 API for the common header-and-body case. It clones the scaffold, builds headers with collectionFromKey, builds rows with collectionFromInternal, and returns JSON. Colgroups, footers, or other custom pieces can be composed separately with the same helpers.
