Make a change in the right place

Use this page to orient yourself in the repository, run the browser examples, and decide which source, sample, and documentation files need to move together.

Get the repository running

The docs and browser examples use Vite to serve local ES modules and JSON imports.

Install dependencies

npm install

Start the local server

npm run dev

Open the URL Vite prints, then visit /docs/index.html.

npm run build runs the configured Vite build. The current package.json has no test script; browser examples are useful for checking the end-to-end JSON-to-renderer path.

A small change workflow

For a behavior change

Make the change under src/v12, keep the public entry re-exporting that implementation, and update the input/output example that explains the changed behavior.

For a new composition pattern

Add a sample beside the existing cases. Keep data, templates, scaffold, and instruction data separate so readers can see which part controls each result.

For a docs change

Put package usage in the user guide, contributor steps here, and design contracts or data flow in the architecture guide. Keep docs/README.md as the detailed API reference.

How sample folders are organized

Instruction-driven examples use JavaScript as the small interpreter for JSON instruction records.

sampleData.json       values to place in the table
sampleSpec.json       tag templates and placeholders
table.json            outer table shape and insertion points
instuctions.json      source + template + helper + destination
index.js              imports these pieces and applies each instruction

The current fixture filename is spelled instuctions.json. If renaming it, update every import and link in that sample together.

The current four cases are at different stages: columns has two destination paths that miss the row index; rows and rows_good select a bare row template, so their generated body rows have no cells. The architecture guide explains the cases and the instruction contract.
